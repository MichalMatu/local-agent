# Local Agent 4.20.6

## Summary

Local Agent 4.20.6 hardens production queue admission against repeated equivalent tasks generated by overlapping conversations. The immutable `v4.20.6` release tag shipped with Chat Bridge `0.8.1`.

A verified post-release source patch on the same Local Agent 4.20.6 line advances Chat Bridge to `0.8.2` for browser-native Conversation Fabric child delegation inside the operator's already authenticated primary Chrome session. Local Agent execution authority, task schema, repository binding and deterministic executor semantics are unchanged.

## Queue deduplication changes

- Add deterministic execution fingerprints that ignore task ids and cosmetic stage/timeout/output metadata while retaining actual edit/command effects.
- Add optional stable branch-scoped `dedupe_key` intent identities so separate chats can converge on one logical task.
- Coalesce equivalent pending tasks in the production parallel repository worker before task commands run.
- Publish terminal `duplicate_task_suppressed` evidence for suppressed duplicates, pointing at the original task.
- Keep short durable claim-aware admission/completion receipts so late duplicates are suppressed without blocking legitimate interrupted/corrective work forever.
- Reject malformed explicit dedupe keys before execution with terminal evidence.

## Chat Bridge 0.8.2 post-release patch

- Move production Conversation Fabric child creation into the installed Chat Bridge in the normal authenticated Chrome session.
- Add a dedicated trailing `LOCAL_AGENT_CF` delegate/collect envelope, separate from legacy LAB controls.
- Admit child campaigns only from an exact managed parent conversation/tab.
- Reuse the existing `worker_spawn.js` `chrome.tabs` / `chrome.scripting` transaction and ownership primitives rather than starting a second browser/profile.
- Store campaign/dedupe state in `chrome.storage.session` and keep children reasoning-only with no Local Agent task or machine-command authority.
- Capture bounded stable child results from exact owned child tabs and close only those owned tabs after completion/failure.
- Keep Conversation Fabric pacing GitHub-managed through exact `conversation_controls` plus monotonic `control_generation`; normal child campaigns do not use LAB schedule markers.
- Advance the Bridge content protocol to `14` and add focused Node plus real headless Chromium parent/child DOM coverage.
- Do not introduce CDP as a production control plane, Native Messaging, Local Agent-to-browser RPC, a second scheduler, another ChatGPT profile, cookie migration or a second-login/Cloudflare workflow.

## Operational intent

The queue hardening prevents multiple overlapping conversations from repeatedly running equivalent expensive repository work. The Bridge patch removes the separate-browser authentication boundary that could break Conversation Fabric child creation even while the operator's normal ChatGPT session was already healthy.

The next production gate is one bounded live acceptance after exact-head CI/merge/deploy/reload: one managed parent must visibly create at least two reasoning-only child tabs in the same normal Chrome session, collect stable results, close owned child tabs, synthesize itself and—only if justified—cause at most one exact target-bound Local Agent task.

## Unchanged safety boundaries

- `.agent/tasks` remains the only executable repository-work contract.
- Exact canonical `agent_binding`, registry/control identity, execution-enabled admission, leases/resources and emergency controls are unchanged.
- `local-agent` remains execution-disabled as a Local Agent task target.
- Child chats never receive machine execution authority.
- Local Agent remains a deterministic executor; it does not use a model to infer task equivalence.
