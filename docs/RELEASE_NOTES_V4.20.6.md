# Local Agent 4.20.6

## Summary

Local Agent 4.20.6 hardens production queue admission against repeated equivalent tasks generated by overlapping conversations. The release keeps the existing repository binding, resource, execution-authority and task-command model unchanged while preventing redundant work from reaching the expensive execution path.

Chat Bridge remains 0.8.1.

## Changes

- Add deterministic execution fingerprints that ignore task ids and cosmetic stage/timeout/output metadata while retaining the actual edit and command effects.
- Add optional stable, branch-scoped `dedupe_key` intent identities so separate chats can converge on one logical task even when their deterministic command plans differ.
- Coalesce equivalent pending tasks in the production parallel repository worker before any task commands run.
- Publish terminal `status=done`, `outcome=duplicate_task_suppressed` evidence for suppressed duplicates, including the original task id and suppression reason, instead of leaving duplicate queue entries to run later.
- Keep short durable local admission/completion receipts so late duplicates arriving while the original task is active or shortly after completion are suppressed.
- Make active admission receipts claim-aware: once interruption/cancellation recovery removes the original durable claim, the receipt stops blocking a legitimate corrective task.
- Reject malformed explicit dedupe keys before execution with terminal `invalid_dedupe_key` evidence.
- Add focused regression coverage for exact-effect duplicates, explicit intent keys, branch scoping, active claims, interrupted admissions, recent completions and invalid keys.

## Operational intent

This release is specifically intended to stop patterns such as several ChatGPT conversations independently queueing the same Growclip fix and then causing repeated PlatformIO tests, firmware builds and repository-wide verification on unchanged source.

Repository planner policy should still inspect active/pending/recent terminal work before creating tasks. Runtime dedupe is the fail-safe when planners race or overlap; it is not a substitute for good queue hygiene.

## Scope and unchanged safety boundaries

- The production parallel repository worker gains dedupe admission. The serial fallback keeps its existing pre-4.20.6 queue path in this bounded release.
- `.agent/tasks` remains the only executable repository-work contract.
- Exact canonical `agent_binding`, registry/control identity, execution-enabled admission, repository leases, resource admission and emergency disable are unchanged.
- Local Agent remains a deterministic executor; it does not infer task equivalence with a model.
- No OpenAI API reasoning path, new machine authority, or Chat Bridge protocol change is introduced.
